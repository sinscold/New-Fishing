# CLAUDE.md — мод на рыбалку (NeoForge 1.21.1)

Этот файл читает Claude Code в начале каждой сессии. Держи его актуальным: поменялось решение — поправь здесь.

## О проекте

Мод для Minecraft переделывает рыбалку:
- большая удочка (размером со спиннинг) и пиксельная леска;
- модификации удочки: обычный крючок, незеритовый крючок, незеритовая леска;
- лут в воде зависит от биома поплавка и биома игрока;
- рыбалка в лаве, только в Незере;
- новые рыбы: Лавакарп и Обсидиановый сом;
- зелье из Лавакарпа: огнестойкость + поджог цели при любом ударе;
- водяной и лавовый ящики с лутом.

Полный дизайн, таблица биомов и roadmap лежат в документе «Мод «Рыбалка» — NeoForge 1.21.1: идеи и Roadmap» (Claude Docs). Если код расходится с документом, сначала спроси, что правильно.

## Стек

- Minecraft **1.21.1**, NeoForge **21.1.x**, ModDevGradle (MDK `NeoForgeMDKs/MDK-1.21.1-ModDevGradle`)

- IntelliJ IDEA + плагин Minecraft Development

## Команды

```
gradlew runClient     # запустить игру с модом
gradlew runServer     # выделенный сервер (проверка, что клиентский код не грузится на сервере)
gradlew runData       # data generation, если подключим datagen
gradlew build         # собрать .jar в build/libs/
```

На Windows: `gradlew.bat ...` или `.\gradlew ...`.

## Правила кода

- Производительность: не добавлять проверки каждый тик, если есть единоразовый триггер (событие действия: извлечение, смена предмета, клик и т.п.). Если периодическая проверка всё же нужна как запасная, то не чаще раза в 10+ тиков.
- Рендер своих моделей вершинами вручную: в `setOverlay` передавать `OverlayTexture.NO_OVERLAY`, а не 0 (ноль = красный фильтр «получил урон»).
- Всё, от чего зависит физика или вид сущности, должно синхронизироваться с клиентом (`SynchedEntityData`): клиент тоже выполняет `tick()`, и несинхронные поля дают расхождения.
- Всё регистрируется через `DeferredRegister` (`DeferredRegister.Items`, `DeferredRegister.create(Registries.X, MODID)`), на мод-шине в конструкторе главного класса.
- Идентификаторы: `ResourceLocation.fromNamespaceAndPath(MODID, "name")`. Конструктор `new ResourceLocation(...)` в 1.21 убран.
- Данные на предметах хранятся в **Data Components** (`DataComponentType`), не в NBT. Модификации удочки (крючок, леска) — это свой компонент.
- Клиентский код (рендеры, `ItemProperties`, `EntityRenderersEvent`) держи только в `client/` и регистрируй через `@EventBusSubscriber(value = Dist.CLIENT)`. Иначе выделенный сервер упадёт.
- Логику лута по возможности выносим в JSON: loot tables, `minecraft:location_check` для биома поплавка, своё условие для биома игрока, GLM для вмешательства в ванильную `minecraft:gameplay/fishing`.
- Пути в данных пишутся в единственном числе: `loot_table`, `recipe`, `tags/item`. Старые гайды с `loot_tables`/`recipes` для 1.21 не подходят.
- Любой новый предмет требует: регистрацию, модель, текстуру, строку в `ru_ru.json` и `en_us.json`, добавление во вкладку креатива.
- Имена в коде на английском (`lavacarp`, `obsidian_catfish`, `netherite_hook`, `netherite_line`, `water_crate`, `lava_crate`), в `ru_ru.json` — русские названия.

Всё в `src/main/resources/assets/newfishing/`. Имена файлов только строчными латинскими буквами, цифрами и `_`.

## Настройки, биомы, совместимость

- **Настройки игрока** (`Config.java`, файл `config/newfishing-common.toml`; в игре: Моды → New Fishing → Настройки, либо мод Configured): шанс выловить водяной ящик вместо сокровища (`waterCrateChance`), шанс лавового ящика (`lavaCrateChance`), шансы групп и подгрупп лута обоих ящиков (список в `Config.CHANCES`), список отключённых предметов ящиков (`disabledCrateItems`, например `"minecraft:saddle"`). Шансы групп в JSON-таблицах ящиков стоят через условие `newfishing:config_chance` (ключ и значение по умолчанию), отключённые предметы убираются при раскрытии ящика (`CrateBlockEntity.unpackLootTable`). Чтобы добавить новый настраиваемый шанс: строка в `Config.CHANCES`, условие в JSON, перевод в `lang`.
- **Рыбалка по биомам временно убрана** (по просьбе Синса). Остался `loot/FishingModifier.java`: заменяет ванильное сокровище водяным ящиком. Код биомов (`loot/FishingBiomes.java` и прежняя версия `FishingModifier`) лежит в git-истории (коммит «Торговля рыбаков, пиксельная леска, рыбалка по биомам, настройки…») и легко возвращается; таблица шансов биомов — в `ROADMAP.md`.
- **Торговля рыбаков:** `event/FisherTrades.java` (новичок: 8–16 одной рыбы за 1 изумруд, до 4 сделок; мастер: 2–4 рыбы из Незера за 3–4 изумруда, до 3 сделок).
- **Пиксельная леска:** `client/BobberRenderer.java` (рисуется в 2D по сетке: плоскость через концы лески повёрнута вокруг неё к камере, кривая растеризуется по клеткам плоскости; размер пикселя `PIXEL`, палитра из трёх оттенков по виду лески от Синса: обычная #747474/#646464/#646464, фантомная #c3b9a1/#a99b87/#a99b87, незеритовая коричневая; начало лески сдвигается константами `THIRD_*` и `FIRST_*`).
- **Тестирование совместимости (Farmer's Delight, Curios и т.п.):** положить jar'ы модов (под NeoForge 1.21.1) в папку `run/mods/` проекта и запускать `gradlew runClient` как обычно; либо для компиляции с API мода добавить в `build.gradle` репозиторий и зависимость `compileOnly` плюс `localRuntime` (только для запуска). Папка `run/` не коммитится.

## Ключевые решения

- Зелье возвращения (бутылка с зельем, `newfishing:return`; варка: неловкое зелье + потроха пустотной щуки): игрок выпил — телепортируется на точку возрождения; на месте, где выпил, появляется портал на его точку возрождения, а у точки возрождения появляется портал обратно на место, где выпили; порталом может пользоваться кто угодно, но каждым порталом один раз; портал живёт 10 минут. Реализовано эффектом `ReturnEffect` и порталами `ReturnPortal` (ждёт проверки).
- Нож для разделки: ножи Farmer's Delight, а без них любой топор или любой меч (тег `newfishing:knives`). Фантомный скат даёт 2 мембраны. Спрайты рыб пустоты Синс сделает (пока заглушки).
- Фантомная леска (`phantom_line`): 4 мембраны фантома + любой топор бесформенно (топор теряет 1 прочность и остаётся). Нужна для рыбалки в «пустоте»: зона в Крае (`Level.END`), Y от 10 до 50, поплавок там повисает на любой высоте и двигается рывками на 2–5 блоков (почти горизонтально, средняя скорость 0,15 блока/тик, по высоте жёстко зажат в зоне, разгон и плавное замедление, одиночные частицы эндер-жемчуга из поплавка); при поклёвке резко и быстро улетает в сторону (6–10 блоков за 12 тиков); дальше 40 блоков от игрока (по горизонтали) рывки разворачиваются к нему, дальше 80 блоков леска обрывается; нужен эндер-поплавок (остальные поплавки тонут); ловится долго (ожидание 300–1000 тиков), 50/50 между двумя рыбами (`gameplay/void_fishing.json`). Поклёвка в пустоте: звук разбивающегося глаза эндера, вспышка и мерцание частиц `END_ROD` над поплавком. Эндер-поплавок рисуется с текстурой `bobber/ender_hook.png`. В воде фантомная леска работает как любая, в лаве нет (нужна незеритовая). Не рвётся (решение по умолчанию). Для неё отдельные спрайты удочки (виды 11–15: `phantom_line`, `phantom_and_float`, `phantom_and_netherite`, `phantom_with_carrot`, `phantom_with_warped_fungus`); спрайта «закинута» пока нет, используется `used`.
- Рыбы пустоты: фантомный скат (`phantom_ray`) разделывается ножом на мембраны фантома (сейчас 2); пустотная щука (`void_pike`) разделывается ножом на филе (`void_pike_fillet`, при съедании телепортирует как плод хоруса) и потроха (`void_pike_guts`, для зелья возвращения). Нож — предмет из тега `newfishing:knives` (ножи Farmer's Delight, запасной вариант — мечи). Доска Farmer's Delight пока не поддержана.
- В лаве выдерживает только полный незеритовый комплект: любая леска кроме незеритовой сгорает сразу (рыбалка отменяется, сообщение «Леска сгорела!»), обычный крючок тоже («Поплавок сгорел!»); ванильный поплавок тоже сгорает (`LineBreak.burn`).
- Слепое око (`blind_eye`): 8 осколков аметиста вокруг ока эндера; ПКМ запускает (не летит, парит и качается 10 секунд), затем 80% падает предметом, иначе разбивается. Эндер-поплавок (`ender_hook`) = слепое око + обычный крючок: все поплавки в пустоте Края тонут, а этот зависает в ней (единственный, кто может там рыбачить, вместе с фантомной леской). В лаве, как обычный крючок, сгорает.
- Если во время рыбалки достать деталь из удочки, рыбалка отменяется (мгновенно по событию извлечения детали; запасная проверка раз в 10 тиков, `RodMods.holdsFishableRod`). Звуки лавы: `lava_blop` (поплавок вошёл в лаву) и `lava_bulb` (клёв в лаве). В лаве клёв и анимации идут везде (на незеритовой леске), а улов только в Незере. Портал возвращения: после перемещения 2 секунды игрок не входит ни в один портал. Лавовый ящик: звуки блока как у незерского кирпича (открытие/закрытие пока от бочки, Синс попробует сделать свой). Лут лавового ящика (`chests/lava_crate.json`): группы независимы, шанс группы = вероятность её появления; внутри группы подгруппы тоже независимы (шанс подгруппы = вероятность её появления, число предметов = «N любых»), шансы предметов равны/заданы весами. Материалы 100% (подгруппы 50/25/12,5/6,25%), еда 75% (2 предмета), снаряжение 50% (подгруппы 18,75/18,75/6,25/6,25%), инструменты 50% (подгруппы 43,75/6,25%).
- Ящики рисуются своей моделью из Blockbench (`CrateGeometry`, `CrateRenderer`, в инвентаре `CrateItemRenderer`); исходник `models-src/crate.bbmodel`, текстуры `textures/entity/crate/water_crate.png` и `lava_crate.png`. Модели поплавков (`models-src/fishing_hook.bbmodel`, `netherite_fishing_hook.bbmodel`, текстуры в `textures/entity/bobber/`) лежат в проекте, их рендерер будет сделан вместе с пиксельной леской.
- Лавовая рыбалка (улов) работает только в измерении `Level.NETHER` и только с незеритовым крючком **и** незеритовой леской.
- Леска и крючок: для воды подходит любая леска (обычная рвётся 1 к 7, незеритовая не рвётся), для лавы в Незере нужна незеритовая леска, для рыбалки в пустоте — фантомная (ещё не сделано, вопросы 17–21). Обычный крючок рыбачит только в воде (обычный поплавок в лаве сгорает: `VanillaHookLavaEvents`). Незеритовый крючок рыбачит в воде и в лаве.
- Незеритовый поплавок (`NetheriteFishingHook`) плавает на любой жидкости (вода, лава, модовые), клюёт только там, где есть таблица лута: вода — ванильная `gameplay/fishing`, лава — `newfishing:gameplay/lava_fishing` (в Незере и на незеритовой леске), модовая жидкость `ns:path` — `ns:gameplay/fishing/path`. Цепляет и подтягивает существ (подсечка тратит 5 прочности).
- Таблица лавы `newfishing:gameplay/lava_fishing` (лавакарп, сом, незеритовый лом, лавовый ящик; веса правит человек). Бросок: `NetheriteFishingHook` используется, если в удочке незеритовый крючок или фантомная леска. Обычная леска рвётся 1 к 7 при вытаскивании поклёвки (звук `newfishing:line_torn`), незеритовая и фантомная нет. Незеритовый крючок держит добычу втрое дольше. Рендер поплавка пока ванильный.
- Ванильное сокровище из рыбалки убрано глобальным модификатором лута `CrateReplacesTreasureModifier`: каждое сокровище (лук, зачарованная книга, зачарованная удочка, бирка, наутилус, седло) заменяется водяным ящиком.
- Содержимое водяного ящика (`chests/water_crate.json`): 100% до 10 любых досок и до 10 гнилой плоти; 100% 2 продукта до 5 штук (ламинария, свёкла, картошка, морковь, ядовитый картофель, семена свёклы); 1 к 6 до 2 предметов (удочка или лук с чарами и прочностью, книга или зачарованная книга, седло, бирка, наутилус); 1 к 10 до 2 предметов кожаной брони с чарами и прочностью; плюс 0,5% на незеритовый крючок и 0,5% на незеритовую леску. Лавовый ящик уменьшен на 25%.
- Биом поплавка = точка `ORIGIN` в контексте лута рыбалки. Биом игрока берём через владельца поплавка (`THIS_ENTITY` → `getPlayerOwner()`).
- Пиксельная леска — последний этап (только визуал, сложный рендер).
- Удочка одна: изменяем ванильную `minecraft:fishing_rod` (компоненты, события, ресурсы), отдельного предмета нет; функции те же плюс новые. Прочность 500, урон в руке 2. Крафт без модификаций: 3 палки по диагонали.
- Модификации лежат внутри удочки по механике мешков (bundle), у каждой свой слот с отдельным спрайтом; спрайт удочки меняется от модификаций и от заброса.
- Слоты удочки: компонент `newfishing:rod_mods` (леска, крючок). Вставка/извлечение в инвентаре как у мешка: ПКМ предметом на курсоре по удочке или пустым курсором (сначала достаётся крючок). Что можно вставить — теги `newfishing:rod_lines` и `newfishing:rod_hooks`. Без лески и крючка удочка не закидывается (сообщение над хотбаром); смотать закинутую можно.
- Незеритовая леска: рыбалка в лаве и леска не рвётся. Незеритовый крючок: рыбалка в лаве и добыча держится дольше (большое окно для реакции).
- Крючок позволяет рыбачить: без лески и рыболовного крючка удочка не закидывается. Незеритовый крючок: незеритовая пыль + обычный крючок.
- Рецепты: обычная леска — 4 обычные нити (`minecraft:string`) крестом (центр пустой); обычный крючок — 3 железных самородка буквой V («как ведро»); удочка — 3 палки по диагонали. Золотая нить называется `gold_string` («Золотая нить»), лесок из золота нет, незеритовая леска — `netherite_line`.
- Ванильные рецепты удочки, морковки на палке и гриба на палке убираются (`RemoveVanillaRecipes`). В слот крючка вместо него вкладываются обычные морковка (`minecraft:carrot`) и искажённый гриб (`minecraft:warped_fungus`) как приманка (тег `newfishing:rod_riding_sticks`); рыбачить с ними нельзя. Готовые морковка и гриб «на палке» больше не крафтятся. Управление свиньёй/лавоходом сделано через Mixin (`PigMixin`, `StriderMixin`, конфиг `newfishing.mixins.json`): удочка в руке с морковкой/искажённым грибом в слоте крючка рулит, ПКМ даёт ускорение (морковка тратит 7 прочности, гриб 1).
- Curios — необязательная зависимость (`compat/CuriosCompat`, `compileOnly` на jar из `run/mods/`): предмет `bait_bag` («Сумка для наживки») регистрируется, только если Curios установлен, лежит в слоте `belt` (тег `data/curios/tags/item/belt.json`). Надетая сумка при забросе возвращает приманку и везучего рыбака до ванильных значений (удвоение): любой заброс идёт через `NetheriteFishingHook`. Спрайт `textures/item/bait_bag.png` пока заглушка (копия крючка). Крафта нет. - Пачка сигарет (пасхалка, секрет): `cigarette_pack` (`CigarettePackItem`) работает как мешок только для сигарет: компонент `newfishing:cigarettes` (0–20, вылавливается полной), секретный дроп из лавы (вес 0,5 в `lava_fishing.json`), лежит в ванильной вкладке еды. ПКМ пустым курсором по пачке в инвентаре достаёт 1 сигарету (`CigaretteEvents`), ПКМ свежей сигаретой на курсоре кладёт обратно, ПКМ пачкой в руке даёт сигарету в инвентарь. Сигарета `cigarette` (`CigaretteItem`): закуривается ПКМ в правой руке, зажигалка (тег `newfishing:lighters`, сейчас только огниво) в левой, тратит 1 прочность зажигалки. Сигареты не стакаются (1 в слоте); при первой затяжке сигарета получает прочность 3 (компоненты `MAX_DAMAGE`, `DAMAGE`), в пачку надкуренная не возвращается. Поза при закуривании `UseAnim.SPYGLASS` (как подзорная труба); в инвентаре и на земле спрайт Синса `cigarette.png`, в руках его зеркальная копия `cigarette_mirrored.png` (модель `item/generated`, без своих display); прежняя 3D-палочка вдоль оси Z лежит в `models-src/archive/`. Дым при курении появляется в 0,9 блока от лица, чтобы не заслонять экран. Закуривание ничего не даёт, кроме скрытого достижения `newfishing:kayf` «Кайф». Модель пачки в руках 3D (`cigarette_pack.json`; у полной пачки крышка закрыта, у неполной и пустой открыта), в инвентаре спрайты по состоянию (`cigarette_pack_full/half/empty.png`, предикат `newfishing:pack_state`: 0 полная, 1 неполная, 2 пустая; предикаты моделей срабатывают при значении «не меньше», поэтому полная = базовая модель); спрайт сигареты `cigarette.png` заглушка 16×16.

## Работа вдвоём

- Работаем прямо в `main` (решение человека). Sinscold делает только `git pull`; Claude коммитит и пушит в `main` без PR.
- Перед работой всегда `git pull`.
- Маленькие коммиты с понятным сообщением на русском: `Этап 1: добавлены рыбы и ящиков`.
- Не коммитить `build/`, `run/`, `.gradle/`, `.idea/` (они уже в `.gitignore`).
- Перед push проверить, что `gradlew runClient` запускается без ошибок.
- Баги заводим в GitHub Issues: что делал, что ожидал, что вышло, кусок `run/logs/latest.log`.

## Как проверять работу

Claude не может запустить Minecraft. После каждого изменения:
1. Человек запускает `gradlew runClient`.
2. Проверяет по чеклисту этапа из roadmap.
3. Если упало, присылает ошибку из консоли или `run/logs/latest.log`.
