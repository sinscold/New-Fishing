# Мод «Рыбалка» — NeoForge 1.21.1: идеи и Roadmap

Nov 14, 2026 · @Cattail

## О моде

Мод переделывает рыбалку: красивая удочка, апгрейды крючка и лески, лут зависит от биома, а в Незере можно рыбачить в лаве. Сверху — две новые рыбы, новое зелье и два вида кейсов с лутом.

**Стек:**

| Что | Версия / инструмент |
| --- | --- |
| Minecraft | 1.21.1 |
| Загрузчик | NeoForge 21.1.x (MDK с neoforged.net) |
| Язык | Java 21 (JDK 21, например Temurin) |
| IDE | IntelliJ IDEA Community + плагин Minecraft Development |
| Сборка | Gradle (идёт в MDK, команда `gradlew runClient`) |
| Текстуры | Aseprite / LibreSprite / Blockbench (16×16 и 32×32 пиксели) |
| Код и обмен | Git + GitHub (приватный репозиторий на двоих) |

Рабочее название мода пока не выбрано — нужен короткий `modid` латиницей (например, `deepfishing`), он попадёт во все пути файлов, менять его потом больно.

## Идеи по модулям

Идея распадается на 7 независимых модулей — их можно делать и тестировать по одному.

**1. Визуал удочки**

- Пиксельная леска вместо тонкой ванильной линии (квадратики вдоль кривой).
- Спрайт удочки увеличен до размера спиннинга (в руке и на модели игрока).

**2. Модификации удочки**

| Деталь | Что даёт |
| --- | --- |
| Обычный рыболовный крючок | Рыбалка в воде (базовая деталь) |
| Незеритовый крючок | Часть комплекта для лавы |
| Незеритовая леска | Часть комплекта для лавы (не горит) |

Крючок + леска из незерита вместе = можно рыбачить в лаве в Незере.

**3. Водная рыбалка по биомам**

- Лут зависит от двух биомов: где поплавок и где стоит игрок (например, поплавок в реке, игрок в джунглях).
- У каждого биома свой шанс сокровища и мусора (черновик таблицы — ниже).
- Из воды может попасться водяной кейс.

**4. Лавовая рыбалка (только Незер)**

- Механика как в ваниле, но в лаве и только в измерении Незер.
- Лут: часто обсидиан, редко незеритовый лом, лавовый кейс.
- Новые рыбы клюют почти сразу: **Лавакарп** и **Обсидиановый сом**.

**5. Зелье из Лавакарпа**

- Даёт огнестойкость + эффект «заговор огня» на любом ударе (меч, рука, что угодно).

**6. Переработка Обсидианового сома**

- Раскалывается на филе + обсидиан.

**7. Кейсы с лутом**

| Кейс | Обычный лут | Редкий лут |
| --- | --- | --- |
| Водяной | Доски, водоросли, кожаная броня, овощи, гнилая плоть | Сокровище (что именно — уточнить) |
| Лавовый | Обсидиан, незерские кирпичи, незерские наросты, стержни ифрита, золотые инструменты и оружие | Алмазы, железо, незерит, незеритовый лом; самое редкое — шаблон улучшения и алмазные вещи (с шансом зачарования) |

## Таблица биомов (черновик)

В ваниле без зачарований расклад такой: рыба 85%, мусор 10%, сокровище 5% (и сокровище только в «открытой воде»). Ниже — стартовые цифры для обсуждения, их надо будет подкрутить после тестов.

**Биом поплавка** — задаёт основные шансы:

| Биом поплавка | Рыба, % | Мусор, % | Сокровище, % | Особенность |
| --- | --- | --- | --- | --- |
| Река / замёрзшая река | 88 | 8 | 4 | Больше лосося |
| Океан (обычный, холодный) | 85 | 9 | 6 | Ванильный баланс |
| Глубокий океан | 80 | 10 | 10 | Лучшее место для сокровищ |
| Тёплый океан | 85 | 7 | 8 | Больше тропической рыбы |
| Болото / мангровое болото | 70 | 25 | 5 | Много мусора, слизь |
| Пляж / каменистый берег | 82 | 13 | 5 | Больше досок и водорослей |
| Грибные поля | 75 | 10 | 15 | Редкий биом = бонус |
| Всё остальное (озёра в лесу, равнине и т.д.) | 85 | 10 | 5 | Как в ваниле |

**Биом игрока** — даёт небольшой модификатор и свои предметы в мусоре:

| Биом игрока | Эффект |
| --- | --- |
| Джунгли | В мусоре бамбук и какао-бобы |
| Тайга / снежные биомы | В мусоре еловые доски, лёд; больше лосося |
| Пустыня / саванна | В мусоре кактус, кости |
| Грибные поля | +3% к сокровищу |
| Любой другой | Без изменений |

Лавовая рыбалка биомы не учитывает (по идее автора) — ей хватит одной таблицы лута на весь Незер.

## Как это делается в NeoForge

Самое сложное в моде — лавовый поплавок и пиксельная леска; предметы, кейсы и лут в основном делаются JSON-файлами.

| Фича | Как реализовать | Сложность |
| --- | --- | --- |
| Новые предметы (рыбы, крючки, леска, филе, кейсы) | `DeferredRegister.Items` + модели, текстуры, перевод в `lang/ru_ru.json` и `en_us.json` | Легко |
| Увеличенная удочка | Текстура 32×32 или блок-модель из Blockbench + `display`-масштаб в JSON-модели; состояние «закинута» — через item property `cast` | Легко |
| Модификации удочки | Свой Data Component на удочке (какой крючок, какая леска) + рецепт установки (кузнечный стол или свой рецепт крафта) + подсказка в tooltip | Средне |
| Пиксельная леска | Свой рендерер поплавка (аналог ванильного `FishingHookRenderer`), рисует кривую маленькими квадратами вместо линии; регистрация в `EntityRenderersEvent.RegisterRenderers` | Сложно (рендер) |
| Лавовый поплавок | Своя сущность-поплавок по образцу ванильного `FishingHook`: проверка `FluidTags.LAVA` вместо воды, невосприимчивость к огню, проверка измерения `Level.NETHER`, свои частицы; удочка (наследник `FishingRodItem`) выбирает, какой поплавок бросить | Сложно |
| Лут по биому поплавка | Ванильное условие `minecraft:location_check` в таблице лута — у рыбалки точка проверки и есть поплавок | Легко (JSON) |
| Лут по биому игрока | Своё условие лута (`LootItemCondition`): берёт поплавок из контекста, из него — игрока и его биом | Средне |
| Изменение ванильной рыбалки | Global Loot Modifier на `minecraft:gameplay/fishing` (совместимо с другими модами) или, для начала, просто переопределить таблицу | Средне |
| Кейсы | Предмет с ПКМ: бросает свою таблицу лута и выдаёт предметы; зачарования — функции `enchant_with_levels` + `random_chance` в JSON | Легко |
| Зелье из Лавакарпа | Свой `MobEffect` «огненный удар» (событие урона → поджечь цель) + `Potion` с огнестойкостью и этим эффектом + рецепт варки в `RegisterBrewingRecipesEvent` | Средне |
| Раскалывание сома | Проще всего: крафт сом → филе, а обсидиан остаётся в сетке как «остаток» (`craftRemainder`); или ПКМ киркой | Легко |

Примечание: в 1.21 папки датапака называются в единственном числе (`loot_table`, `recipe`), старые гайды с `loot_tables` уже не работают.

## Roadmap

Порядок построен так, чтобы после каждого этапа мод запускался и что-то новое можно было потрогать в игре. Пиксельная леска ушла в конец: это чистый визуал и самая сложная часть рендера.

**Чеклист «этап готов, когда…»**

- [ ] **0.** Игра запускается через `runClient` у обоих, мод виден в списке модов.
- [ ] **1.** Все новые предметы есть в творческой вкладке, с текстурами и названиями на русском.
- [ ] **2.** Удочка крупная в руке; крючок и леска ставятся рецептом и видны в подсказке.
- [ ] **3.** В Незере с незеритовым комплектом поплавок не сгорает и ловит Лавакарпа, сома, обсидиан; в Обычном мире в лаве — не ловит.
- [ ] **4.** В болоте заметно больше мусора, в глубоком океане — сокровищ; биом игрока меняет мусор.
- [ ] **5.** Оба кейса ловятся и открываются ПКМ, иногда дают зачарованные вещи.
- [ ] **6.** Зелье варится, удар рукой поджигает моба; сом раскалывается на филе и обсидиан.
- [ ] **7.** Леска рисуется пикселями; шансы проверены на 50+ забросах; собран релизный `.jar`.

## Открытые вопросы

Эти вещи нужно решить до того этапа, где они нужны — остальное можно начинать уже сейчас.

- [ ] Название мода и `modid` (Этап 0).
- [ ] Модификации: это детали, которые ставятся на одну удочку (и снимаются?), или просто отдельная «незеритовая удочка»? Второе намного проще.
- [ ] Зачем нужен «обычный крючок», если ванильная удочка и так ловит в воде? Например: без него — ванильный лут, с ним — лут по биомам.
- [ ] Как крафтятся крючки, леска и незеритовые версии (через кузнечный стол с слитком незерита?).
- [ ] Что именно лежит в «сокровище» водяного кейса.
- [ ] Как часто ловятся кейсы (предлагаю: часть таблицы сокровищ, \~1–2% от улова).
- [ ] Баланс лавового кейса: незерит и шаблоны улучшения легко ломают экономику — нужны очень маленькие шансы (доли процента).
- [ ] Зелье: длительность, есть ли усиленная/долгая версия (светокаменная пыль / редстоун), сколько секунд горит цель.
- [ ] Филе сома: естся сырым, жарится, или это ингредиент?
- [ ] Пиксельная леска — только для удочек мода или и для ванильной тоже?

## Работа вдвоём через GitHub

Код живёт в одном репозитории на GitHub: кто пишет — делает `push`, кто тестирует — делает `pull` и запускает игру.

**Один раз настроить**

1. Создатель репозитория: Settings → Collaborators → добавить друга по нику.
2. Каждому: поставить Git, JDK 21 и IntelliJ IDEA.
3. Скачать проект: `git clone <ссылка на репозиторий>`.
4. Открыть папку в IntelliJ как Gradle-проект и дождаться первой синхронизации (первый раз качает Minecraft и NeoForge, это долго).

**Каждый раз, когда что-то новое в облаке**

1. `git pull` — забрать свежие изменения.
2. `gradlew runClient` (или запуск `runClient` в IntelliJ) — откроется Minecraft уже с модом.
3. Проверить фичу по чеклисту этапа; баги — в GitHub Issues (что делал, что ожидал, что случилось, скриншот или `logs/latest.log`).

**Когда сам что-то меняешь** (текстуры, JSON лута):

1. `git pull` перед началом работы.
2. `git add .` → `git commit -m "что сделал"` → `git push`.
3. Если вы оба правили один файл — Git покажет конфликт; проще договориться, кто что трогает.

**Вариант без сборки:** можно добавить GitHub Actions, который после каждого push сам собирает `.jar`. Тогда друг просто скачивает файл из вкладки Actions и кидает в папку `mods` сборки NeoForge 1.21.1 (например, в Prism Launcher) — IntelliJ и JDK ему тогда не нужны.
